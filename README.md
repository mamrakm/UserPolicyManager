# User Policy Manager

A Spring Boot REST application for managing users and policies with PostgreSQL persistence.

## Overview

This application provides a robust system for managing users and applying policies based on configurable rules. Each
policy defines one or more conditions that determine if it applies to a user. When a policy is applicable to a user, it
is added to the user's policy array.

## Requirements

**Important**: This project requires Java 21 to run. It uses modern Java features including record patterns, sealed
interfaces, and enhanced pattern matching.

## Features

- **User Management**: Create, read, update, and delete user profiles
- **Policy Configuration**: Define rules that target specific users based on attributes
- **Automatic Policy Evaluation**: Real-time policy evaluation and application
- **RESTful API**: Well-defined endpoints for integration
- **PostgreSQL Storage**: Data persistence using JPA and PostgreSQL
- **Event-driven Architecture**: Uses Spring events for policy evaluation

## Configuration Guide

### Creating Users

Users can be created by sending a POST request to `/api/users` with a JSON payload:

```json
{
  "name": "jdoe",
  "firstName": "John",
  "lastName": "Doe",
  "emailAddress": "jdoe@evolveum.com",
  "organizationUnit": [
    "Software Development",
    "Support"
  ],
  "birthDate": "2007-09-07"
}
```

Note: The `registeredOn` field is automatically set to the current date during creation. The `policy` array is computed
automatically based on the applicable policies.

### Creating Policies

Policies can be created by sending a POST request to `/api/policies` with a JSON payload containing one of the supported
rule types:

1. **YoungerThan Rule**:

```json
{
  "id": "underaged",
  "name": "Underaged User",
  "youngerThan": {
    "value": 18
  }
}
```

2. **EmailDomainIs Rule**:

```json
{
  "id": "internal-user",
  "name": "Internal User",
  "emailDomainIs": {
    "value": "evolveum.com"
  }
}
```

3. **IsMemberOf Rule**:

```json
{
  "id": "developer-full-access",
  "name": "Developer (Full Access)",
  "isMemberOf": {
    "value": "Software Development"
  }
}
```

## System Behavior

1. When a user is created or updated, the system automatically evaluates all policies and applies those that match the
   user's attributes.

2. When a policy is created, updated, or deleted, the system re-evaluates all users and updates their policy arrays
   accordingly.

3. The policy evaluation happens in real-time, ensuring that user permissions are always up-to-date.

## Examples

### Example 1: Creating an underaged internal user who is a developer

1. Create the policies first (if not already existing):

```bash
# Create underaged policy
curl -X POST http://localhost:8080/api/policies -H "Content-Type: application/json" -d '{
  "id": "underaged",
  "name": "Underaged User",
  "youngerThan": {
    "value": 18
  }
}'

# Create internal user policy
curl -X POST http://localhost:8080/api/policies -H "Content-Type: application/json" -d '{
  "id": "internal-user",
  "name": "Internal User",
  "emailDomainIs": {
    "value": "evolveum.com"
  }
}'

# Create developer policy
curl -X POST http://localhost:8080/api/policies -H "Content-Type: application/json" -d '{
  "id": "developer-full-access",
  "name": "Developer (Full Access)",
  "isMemberOf": {
    "value": "Software Development"
  }
}'
```

2. Create the user:

```bash
curl -X POST http://localhost:8080/api/users -H "Content-Type: application/json" -d '{
  "name": "jdoe",
  "firstName": "John",
  "lastName": "Doe",
  "emailAddress": "jdoe@evolveum.com",
  "organizationUnit": [
    "Software Development",
    "Support"
  ],
  "birthDate": "2007-09-07"
}'
```

3. Check the user to see the applied policies:

```bash
curl -X GET http://localhost:8080/api/users/jdoe
```

The response should show all three policies applied to the user:

```json
{
  "name": "jdoe",
  "firstName": "John",
  "lastName": "Doe",
  "emailAddress": "jdoe@evolveum.com",
  "organizationUnit": [
    "Software Development",
    "Support"
  ],
  "birthDate": "2007-09-07",
  "registeredOn": "2024-05-07",
  "policy": [
    "underaged",
    "internal-user",
    "developer-full-access"
  ]
}
```

### Example 2: Updating a policy and seeing the effects

1. Update the "underaged" policy to change the age threshold:

```bash
curl -X PUT http://localhost:8080/api/policies/underaged -H "Content-Type: application/json" -d '{
  "id": "underaged",
  "name": "Underaged User",
  "youngerThan": {
    "value": 16
  }
}'
```

2. Now, if we have users between 16 and 18 years old, they will no longer have the "underaged" policy applied to them.
   The system automatically recomputes all users when a policy is updated.
